What's New

New Features

  • Agents can now build custom pane types. Each one is a small HTML/JS app in its own folder under ~/Library/Application Support/Addy/Panes/<kind>/, with a pane.json manifest. It renders as a native pane that hot-reloads when its files change.
  • Custom panes get a window.addy bridge. It covers project file read/write/list, shell commands (addy.run), per-project storage, opening URLs in Addy's browser, and theme variables that follow the active theme.
  • Installed custom panes appear in the pane launcher. A new "New Pane Type…" action asks what you want and starts an agent that builds it.
  • Two new agent tools, addy_list_pane_types and addy_open_custom_pane, let agents list installed pane types, read the authoring guide, and open or reload a custom pane. They can then check its text and JavaScript errors with addy_read_pane.
  • Browser panes now show JavaScript alert, confirm and prompt dialogs inline in the pane instead of silently ignoring them.
  • Browser downloads now save straight to ~/Downloads without overwriting existing files. A toast confirms each download with a "Show in Finder" action, or reports the failure.
  • Browser panes now capture console.log, warn, error and info output, plus uncaught errors and rejections. A pane keeps up to 2,000 entries.

Improvements

  • When an agent's browser action triggers a page dialog, it is answered automatically (OK for alerts, Cancel otherwise) so the agent isn't blocked. The agent sees a console warning describing what happened.
  • File pickers in browser panes only open for you, never during agent-driven actions.
  • Hidden browser panes now pause media playback right away. They unload their page after 5 minutes, or immediately under memory pressure, and restore it when you return.
  • Custom panes persist across layouts and restarts. Their data is stored outside the pane folder, so saving it doesn't trigger a reload.
  • Custom pane links to web pages open in Addy's browser pane. Pages from the web can't call the bridge.

Bug Fixes

  • Clicking a download link in the browser pane no longer replaces the page with an error page.
  • Reloading or navigating a hidden browser pane no longer gets confused by the "paused while hidden" placeholder. Its title and URL are no longer overwritten.
  • Fixed the note shown when a page opens in a project you aren't viewing. It now correctly says browser tools can't reach the page until you switch to that project.
