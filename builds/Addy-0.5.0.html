What's New

New Features

  • Added a fast mode toggle (bolt icon) next to the model picker in chat. Toggling fast mode on a Codex session sends a serviceTier: "fast" flag on the existing thread instead of starting a new session. Claude chat fast mode switches to a Haiku model. The toggle is only visible for backends that support it (Claude and Codex).
  • Added browser Direct/Compatibility mode picker in the browser pane header bar. Localhost pages now default to Compatibility Mode (proxy), but you can switch to Direct Mode to preserve the original localhost origin — useful for auth flows, CORS, and OAuth. The mode preference is remembered per project+host+port.
  • Added browser issue detection footer that automatically detects common localhost problems (HMR failures, CSP blocking, CORS errors, auth failures) and suggests switching browser mode with a one-click "Switch Mode" button.
  • Added Compatibility Mode remote API proxy so that localhost apps loaded through the Addy proxy can still reach remote APIs. The proxy rewrites Origin/Referer headers to the real localhost origin and handles cookie bridging, redirect rewriting, and CORS header stripping.
  • Codex chat now handles command execution approval requests — when Codex asks to run a shell command, Addy shows an Allow/Deny permission card instead of silently proceeding.
  • Added an "Approve always" option to permission cards for both Codex and Claude, letting you approve a tool for the rest of the session without repeated prompts.
  • Added a Permissions section to the model selector menu with "Always ask" and "Always allow" modes. The selected mode is persisted in settings and applied to Codex and Claude launch commands automatically.
  • Added a Codex wrapper script that automatically applies --ask-for-approval never and --sandbox workspace-write defaults when Codex runs inside Addy's terminal environment.
  • Server and build panes now persist and restore across app restarts, including their command, process window shape, footer bar state, and owned-child workflow registration.
  • Server panes are now reused when an agent requests the same server command again — instead of creating a duplicate pane, the existing one is restarted.

Improvements

  • Agent-driven pane operations (split, open URL, browser JS evaluation, console open) no longer steal keyboard focus from the pane you're typing in. This includes cross-project scenarios where a background agent mutates panes in a hidden project.
  • Input request auto-focus now checks that the view is actually visible before stealing keyboard focus, preventing hidden/inactive project chat cards from intercepting your typing.
  • addy_focus_pane can no longer make a pane in a hidden or inactive project first responder, preventing cross-project focus stealing via IPC.
  • Cmd+/Cmd-/Cmd+0 font scaling now works correctly in chat panes. Previously, focused text views could intercept the shortcuts before they reached the app. Chat messages, the empty state, and the composer all refresh at the new font size.
  • Terminal scrolling performance dramatically improved for panes with large scrollback buffers. Addy now handles scroll wheel events directly instead of routing through SwiftTerm's per-event overlay scroller animations.
  • Stdout line parser now slices into the incoming chunk directly instead of repeatedly copying into a growing buffer string, reducing allocations during fast streaming output.
  • addy_read_pane now returns the full chat conversation transcript for readable chat panes, without the previous 500-character per-text-block truncation.
  • MCP tool timeout extended from 3 minutes to 60 minutes, preventing premature timeouts on long-running Addy tools like addy_spawn_agents. Codex config now sets tool_timeout_sec=3600 on the Addy MCP server section.
  • Browser pane now uses the default persistent WKWebView data store instead of a non-persistent one, fixing auth-heavy sites like Apple Developer that depend on normal cookie/session behavior.
  • Browser instrumentation, cache-busting, and CSP stripping scripts now only run on localhost pages, leaving real websites untouched.
  • Build panes now use a status marker to detect exit codes, making finite build completion more reliable than relying solely on process exit signals.
  • Background CLI processes (plan reviews, code reviews, inspector agents) now use the resolved absolute binary path from BackendRegistry instead of bare command names, and inherit the user's interactive shell environment — fixing "command not found" errors on machines where claude/codex aren't on the default PATH.
  • Codex config now sets default_tools_approval_mode = "approve" on the Addy MCP server section, ensuring tool permissions flow through Addy's approval UI.
  • Chat card spacing and header padding refined for a cleaner look in both light and dark themes.
  • HTML responses from localhost dev servers are now rewritten to keep asset and WebSocket URLs pointing at the proxy origin, preventing broken resources when loading through Compatibility Mode.
  • Plan and code review results are now stored by plan ID, so addy_get_plan_review and addy_get_code_review return findings for the correct plan instead of stale project-level results.
  • Plan review start/create/update responses now include the active review profile summary, making stale model configuration visible immediately.
  • Failed plan reviewers now correctly resolve as failures instead of silently counting as clean, preventing false "no issues found" results after a reviewer timeout.

Worktree management improved

  • Prunable worktrees are now tracked, duplicate sidebar entries are deduplicated, and stored worktree projects are reconciled against actual disk state on branch scan.

Bug Fixes

  • Fixed focus stealing when input request views in hidden/inactive project panes attempted to auto-focus their text fields.
  • Fixed a crash when spawning code review sub-agents caused by Auto Layout constraints being activated on views not yet in the view hierarchy (ReviewAgentStatusView).
  • Fixed cross-project MCP tool routing where an implicit source_pane_id from the calling pane overrode an explicit project_path, causing browser and server panes to open in the wrong project.
  • Fixed attachment preview cards showing a large blank gap above file/image thumbnails by applying proper stack alignment and explicit height constraints.
  • Fixed Codex app-server initialization hanging indefinitely — a 5-second timeout now falls back to legacy transport if the app-server doesn't respond.
  • Fixed user stop during app-server initialization leaving the session in a broken state.
  • Fixed the Direct Mode content rule list failing to compile due to an unsupported URL filter disjunction — split into separate rules for localhost, 127.0.0.1, and [::1].
  • Fixed the owned child pane rail visual artifact being left behind after the rail was removed.
  • Fixed Codex standard/fast mode feeling identical when the user's Codex config had service_tier="fast" globally. Addy now explicitly sends serviceTier:null for standard mode so it isn't inherited from the global config.
  • Fixed stopped-chat resume incorrectly treating a permission-only flag change as a new backend session, dropping the native session ID on restart.
  • Fixed stale plan review results being returned for a different plan than the one being reviewed.
  • Fixed cloud-synced projects without a local path incorrectly showing the "New Branch" context menu action.
  • Fixed sidebar worktree creation not showing an error alert when git worktree add fails.
